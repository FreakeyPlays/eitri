# T3 Code backend reference

Inspected 2026-09-21 at commit `371b52d9dad76876f84609a4cd0f80eaa757b69c`. Scope: local backend, browser/desktop communication, agent integration. These are source observations, not performance measurements.

## Verified architecture

- **The CLI starts and manages the server; it is not an alternative UI transport.** The `t3` command defaults to `runServerCommand`, with explicit start/serve and management subcommands. It runs a Node/Effect runtime. [CLI entry](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/bin.ts#L62-L102)
- **Application RPC uses a persistent WebSocket.** The server upgrades `GET /ws`, authenticates the connection, creates an Effect RPC server from shared `WsRpcGroup`, and serializes JSON. The client creates a WebSocket and matching RPC protocol per environment session. Multiple request methods and streaming subscriptions share that protocol. [Server WS route](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/ws.ts#L3743-L3782); [Client session](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/packages/client-runtime/src/rpc/session.ts#L162-L216); [Shared RPC contracts](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/packages/contracts/src/rpc.ts)
- **HTTP remains deliberate.** The same server composes HTTP APIs, static assets, asset reads, attachment uploads and WebSocket RPC. Some orchestration and pull-request operations also have HTTP APIs; T3 has not eliminated HTTP. [Route composition](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/server.ts#L572-L601); [Asset and upload handlers](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/http.ts#L375-L452)
- **Codex has a separate transport.** The backend spawns `codex app-server` with the session cwd and creates a child-process client. That client drains stderr and communicates using `makeChildStdio`: browser WebSocket RPC is not forwarded directly to Codex. [Codex session process](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/provider/Layers/CodexSessionRuntime.ts#L1300-L1355); [Codex stdio client](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/packages/effect-codex-app-server/src/client.ts#L253-L265)
- **Claude uses its own adapter.** It wraps `@anthropic-ai/claude-agent-sdk` query sessions and converts SDK messages into provider events. This is a separate boundary from UI transport. [Claude adapter](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/provider/Layers/ClaudeAdapter.ts#L1-L27); [Query creation](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/provider/Layers/ClaudeAdapter.ts#L2070-L2155)
- **State and reconnection are explicit.** Server orchestration appends domain events and updates projections inside a SQL transaction, with SQLite persistence. A separate client connection supervisor owns reconnect/backoff; the raw RPC session disables its own retries. Thread subscriptions resume using `afterSequence`, with snapshot fallback. This verifies replay and server-owned state, not a universal guarantee that every operation survives every disconnect. [Orchestration transaction](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/Layers/OrchestrationEngine.ts#L270-L290); [SQLite](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/persistence/Layers/Sqlite.ts); [Connection supervisor](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/packages/client-runtime/src/connection/supervisor.ts#L710-L740); [Thread resume](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/packages/client-runtime/src/state/threads.ts#L812-L845)
- **Slow clients are bounded.** Live subscriptions have an item/byte budget, including delivery awaiting RPC acknowledgement; overflow tells the client to resume from its last sequence. Default limits are 1,000 items and 8 MiB. [Stream budget](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/LiveStreamBudget.ts#L9-L80)
- **Folder selection remains server-aware.** Native folder picking is a desktop bridge capability; the browser implementation returns null without that bridge. The command palette also requests filesystem browsing for the selected server environment. It does not use browser directory handles as backend paths. [Local API](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/localApi.ts#L9-L17); [Environment filesystem browsing](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L1103-L1119)

## Interpretation for Eitri

Eitri already has a server CLI entry and a Tauri sidecar lifecycle; its architecture document already targets Effect RPC over WebSocket. Introducing another CLI is therefore not the central change. Its current agent route starts a fresh CLI process, collects output until completion, then returns. Project selection is not yet connected to an agent cwd. See [architecture](../internals/architecture.md); the accompanying review inspected the current server and Tauri entry points.

Recommended direction, not an implemented decision:

1. Keep one backend owning projects, runs, provider processes and persistence. Desktop starts that backend; browser and desktop use the same application API.
2. Establish shared command/query/event contracts and adapter boundaries. Keep provider-specific subprocess protocols inside provider adapters.
3. Implement one complete vertical slice: start a run for a project, receive incremental events, cancel explicitly, reconnect and recover its current state. Accepted requirement: an active agent continues after a tab closes or disconnects while the server lives. Own runs in a server/session scope separate from the client connection scope, and test this behavior.
4. Use Effect RPC over a shared WebSocket for application commands and subscriptions when implementing streaming. Retain HTTP for files/uploads and other suitable request/response endpoints.
5. Start with persisted run state plus a bounded event sequence/snapshot mechanism sufficient for recovery. Do not copy T3's full event-sourcing/projection system, cloud connectivity or broad provider machinery before Eitri needs them.
6. Measure startup latency, time to first event, event volume, rendering cost and reconnect correctness. There is no evidence here that HTTP overhead is Eitri's present bottleneck. WebSockets enable convenient bidirectional streams; changing transport alone will not fix buffered agent output or repeated process startup.

## Userdata directory and project persistence

### Directory resolution and creation

Default base directory is `~/.t3` (`os.homedir()`), not the repository cwd. Overrides are trimmed, `~`-expanded, and resolved to an absolute path. CLI precedence is `--base-dir` > `T3CODE_HOME` > desktop bootstrap `t3Home` > default. The override is the **base**, not the final userdata directory: `--base-dir /tmp/t3-test` produces `/tmp/t3-test/userdata`. [Base resolution](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/os-jank.ts#L94-L111); [CLI resolution](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/cli/config.ts#L305-L326)

Normally `stateDir = baseDir/userdata`. With a dev web URL and **no explicit CLI/environment base override**, it is `baseDir/dev`. An explicit base override therefore uses `userdata` even in dev; bootstrap-provided base alone does not count as explicit for this switch. [Path derivation](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/config.ts#L129-L164)

Selected normal-mode paths (not every entry exists immediately):

```text
~/.t3/
  userdata/
    state.sqlite
    settings.json
    keybindings.json
    environment-id
    anonymous-id
    server-runtime.json
    attachments/
    logs/
      server.log
      server.trace.ndjson
      provider/events.log
      terminals/
    themes/
    browser-artifacts/
    secrets/
  caches/
  worktrees/
```

These locations are derived centrally. `ensureServerDirectories` eagerly creates state, logs/provider/terminal, attachments, worktrees, and caches directories recursively during CLI config resolution, before the server runs. It does not eagerly create every derived directory/file in this tree. SQLite setup ensures its parent, opens the database, sets WAL/foreign keys/busy timeout and runs migrations. [Directory initialization](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/config.ts#L167-L194); [Startup call](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/cli/config.ts#L320-L330); [SQLite initialization](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/persistence/Layers/Sqlite.ts#L10-L46)

### Projects

Projects live in `userdata/state.sqlite`, rather than a JSON list or one directory per project. The initial migration creates `projection_projects` with `project_id TEXT PRIMARY KEY`, title, workspace root, scripts JSON, creation/update timestamps and nullable deletion timestamp; subsequent migrations evolve the schema. Current repository writes additionally include default model selection JSON, default thread environment mode, auto-pull, favicon and icon JSON. `workspace_root` points to the actual working directory; project identity is its separate `project_id`. [Initial project schema](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/persistence/Migrations/005_Projections.ts#L7-L18); [Current project persistence](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/persistence/Layers/ProjectionProjects.ts#L30-L78)

Create/update/delete are orchestration commands producing persisted events and updating project projections in the same transaction. Create rejects another active project with the same normalized workspace root; metadata update can change the path while retaining project identity. Path normalization trims, expands home and uses `path.resolve`, then checks directory existence/type; it does **not** resolve symlinks with realpath at this boundary. Creation can explicitly request creating a missing workspace. [Commands and uniqueness](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/decider.ts#L226-L327); [Normalization](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/workspace/WorkspacePaths.ts#L152-L190); [Create normalization option](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/Normalizer.ts#L96-L122); [Transactional persistence](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/Layers/OrchestrationEngine.ts#L270-L289)

Deletion marks `deleted_at`, and active project queries filter it out. Deleting a nonempty project requires force, which dispatches thread deletions first. The project projection contains create/update/delete handlers, not a project-restore handler; restarting/reconnecting restores the displayed project list from persisted queries, which is distinct from undoing a deletion. [Delete command](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/decider.ts#L327-L377); [Projection handlers](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/Layers/ProjectionPipeline.ts#L503-L569); [Project read query](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/orchestration/Layers/ProjectionSnapshotQuery.ts#L531-L559)

Client presentation is separate: sidebar project scope, order/expansion and thread last-visited timestamps are in browser localStorage under `t3code:ui-state:v1`. These should not be confused with authoritative backend project records. This bounded inspection did not establish one global last-opened-project field equivalent to Eitri's `lastProjectPath`. [UI state fields](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/uiStateStore.ts#L6-L46); [UI state persistence](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/uiStateStore.ts#L214-L240)

Compared with Eitri's current `projects.json`, the useful design is separating stable project identity and backend domain state from per-client selection preferences. A database is sensible once projects own durable sessions/runs; T3's full event/projection machinery is not necessary merely to remember project folders.

### Exact web and native folder-selection flow

The web UI implements a custom directory browser/path autocomplete inside the command palette. It starts at the selected environment's configured `addProjectBaseDirectory`, falling back to `~/`. Typing a path or navigating directory rows requests `filesystem.browse` with `partialPath` and, for relative paths, the current project's cwd. The UI renders directory rows and parent navigation, with an Add/Create & Add action. [Initial path](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L1058-L1071); [Browse request](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L1103-L1119); [Browse UI and submit](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L2551-L2619)

The RPC handler calls server `WorkspaceEntries.browse`. The server expands `~` in its own environment; explicit relative paths require a project cwd. It reads directory entries from the **server machine**, filters directory names by a case-insensitive prefix, sorts them and returns `parentPath` plus names/full paths. With a trailing separator it lists that directory; otherwise it lists matching children of the input's parent. This is not browser filesystem permission/access: a remote browser browses the connected server's directories. [RPC handler](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/ws.ts#L3059-L3074); [Path resolution](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/workspace/WorkspaceEntries.ts#L112-L132); [Directory enumeration](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/server/src/workspace/WorkspaceEntries.ts#L186-L233)

Electron additionally offers the native folder picker for a matching desktop-local environment, not an arbitrary remote server. `desktopBridge.pickFolder` ultimately uses `Electron.dialog.showOpenDialog` with `openDirectory` and `createDirectory`, returning a path string. WSL has explicit environment/path routing so a Windows path cannot accidentally be submitted to a Linux backend. The web-only local API returns null for native picking; it keeps the custom browser. [Native capability guard](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L2627-L2639); [Picker dispatch](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L2744-L2788); [Electron dialog](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/desktop/src/electron/ElectronDialog.ts#L106-L139); [Web local API](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/localApi.ts#L9-L17)

Both paths converge on the same add-project handler. If that environment already has the path, it opens an existing thread or starts a new one for that project. Otherwise it generates a project ID and submits the title/workspace root, with `createWorkspaceRootIfMissing: true`; the backend validates/normalizes and persists it through the command/projection flow described above. Native picking does not maintain a separate project store. [Existing/new project handling](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L2184-L2250); [Native convergence](https://github.com/pingdotgg/t3code/blob/371b52d9dad76876f84609a4cd0f80eaa757b69c/apps/web/src/components/CommandPalette.tsx#L2832-L2840)
